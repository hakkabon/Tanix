# Syscall coverage

Phase 22 deliverable: every syscall in `kernel/src/ipc/syscall.rs`, its
`tanix-libsys::sys` wrapper, and which server crates actually exercise it
in the current tree. Generated by grepping `sys::<fn>(` call sites
outside `libtanix-sys` itself; regenerate with:

```sh
for fn in send receive spawn who exit_task exit alloc_frames free_frames \
    log wait_irq yield_cpu share_frames unshare_frames sleep exec \
    map_device irq_pending cache_sync sec_storage_put sec_storage_get \
    keybox_gen keybox_seal keybox_unseal attest map_demand map_cow map_cap; do
  callers=$(grep -rl "sys::${fn}(" servers --include=*.rs \
      | grep -v libtanix-sys/src/sys.rs \
      | sed -E 's#servers/([^/]+)/.*#\1#' | sort -u | tr '\n' ',')
  echo "${fn}: ${callers%,}"
done
```

**26 of 27 syscalls have at least one real caller in the tree.**
`SYS_ALLOC_FRAMES` / `SYS_FREE_FRAMES` are asymmetric in caller count but
both are exercised — the imbalance is architectural (most servers
allocate once at startup and never free) rather than a gap.

## Known coverage gaps (candidates for future exercise, not bugs)

- **`SYS_WAIT_IRQ`** has a single consumer (`display`). The Phase 10/11
  `net` server uses the non-blocking `SYS_IRQ_PENDING` poll instead, and
  the Phase 20 `fs` server's virtio-blk path doesn't drive interrupts at
  all yet (it's a synchronous request/completion loop). Extending `fs`
  to `SYS_WAIT_IRQ` on the blk completion IRQ would be a reasonable
  Phase 25 (real hardware) precursor, since polling a real eMMC/UFS
  controller is far more expensive than polling QEMU's virtio-blk.
- **`SYS_MAP_DEMAND` / `SYS_MAP_COW`** are only driven by `init`'s Phase
  19 self-test path, not by any server that would benefit from lazy
  memory in steady-state operation (e.g. `shell`'s `exec` growing a
  process image, or `wm` compositing buffers). Worth revisiting once
  real-hardware memory pressure (Phase 25+) makes eager allocation
  costly.
- **`SYS_SHARE_FRAMES` / `SYS_UNSHARE_FRAMES`** are only exercised by
  `libtanix-ui` (the display server's framebuffer grant to app
  processes). No non-UI server shares memory today, so this path is
  narrower than the syscall's general design would suggest.
- **The Phase 17 secure-service syscalls (18–23)** are, by design,
  exclusive to the `sec` demo server and only meaningful on `sbsa-ref`.
  This is intentional scoping, not a gap — see `servers/sec/src/main.rs`.

## Where this is checked

`ci.yml`'s `lint` job runs `just check` + `just lint-all` (clippy across
the whole workspace) on every push/PR, which catches unused-import/
dead-code drift in this table's caller list. Run `just syscall-coverage`
to regenerate the raw caller list above by hand when adding a syscall or
a new caller; it is not yet wired into CI as an automated diff against
this file (that's the natural next step, left for a follow-up once the
table has shown it's worth enforcing rather than just regenerating).
